# 访客凭证与 Skill 框架

## 已实现

云端连接在保存时请求本站后端封装凭证；回环本机连接使用浏览器加密存储并直连模型，具体边界见 `ARCHITECTURE.md`。浏览器持久保存加密包，关闭标签再打开仍可使用。文章和图片继续保存在本机。访客之间没有公开的凭证查询接口，也不共享服务端 Key 变量。

编辑已保存的连接时只显示“已安全保存，输入新 Key 可替换”，不能从接口回读原始 Key。修改供应商、基础地址或百炼业务空间后，需要重新填写匹配的新 Key。保留原地址时可以修改模型配置。

现有文字、图片、连接发现、官方模型列表接口都可接收加密凭证，并在调用前检查其绑定。新输入但未保存的 Key 仍可测试，不会被持久写入浏览器。所有凭证响应禁止缓存；请求要求 JSON、限制大小并拒绝跨站来源。错误响应不透传供应商原文，避免上游反射密钥。

Kairo Layout 和 Kairo Design 的发布快照在 `server/skills/`。网页只调用固定服务端流程：文章排版、配图规划、图片生成。Skill 更新后重新同步并部署即可。当前没有通用 Agent 执行器，不自动联网查证或执行 Skill 的 Python 脚本。封面有独立看图审核和用户设定额度内的修正流程，具体边界见下文。

## 本机启动

首次执行 `npm run setup:credentials`，生成随机的本地加密配置；重复执行不会替换已有密钥。然后执行 `npm run build` 和 `npm run start:local`。已有服务须先停止再构建。

`.env.local` 已排除版本管理，权限为 600。请单独保管备份；遗失服务端加密密钥会使已保存的访客凭证无法解密。不要把该文件附在问题报告、GitHub 或前端代码中。

## 部署位置与配置

部署整个 Next.js 项目到支持 Node.js Route Handlers 的服务器或托管平台，不能仅上传静态网页。两个 Skill 跟随后端一起部署，不需单独购买 Skill 服务。

1. 在部署平台的秘密配置中设置 `KAIPAI_CREDENTIAL_KEYS`，格式参见 `.env.example`。使用随机 32 字节密钥的 Base64 编码。不要使用示例字符串，不要放入 `NEXT_PUBLIC_*`。
2. 所有实例使用同一份稳定配置；更新网站和扩缩容时保留它。应用会话无数据库，但加密主密钥不能是临时的。
3. 配置 HTTPS。如果代理内部地址与浏览器地址不同，设置 `KAIPAI_PUBLIC_ORIGIN` 为准确的浏览器站点 Origin。公网部署不得启用 `KAIPAI_ALLOW_LOOPBACK_API`。
4. 网关不要记录 API 请求体、Authorization、凭证或模型原始响应。配置入口限流、并发和请求时长限制；Workers 部署使用 `KAIPAI_API_RATE_LIMITER`，其他部署需配置对应入口限流。模型与图片地址做公网检查，但公网出口还应阻断内网及云元数据，覆盖 DNS 重绑定等网络层风险。
5. 可选设置 `KAIPAI_GITHUB_URL` 为真实仓库或个人主页；页脚会显示链接。
6. 使用测试 Key 验证部署环境的保存、重开、调用和错误路径，再接真实模型。保存成功不等于模型可用，模型可用不等于成图质量通过。

首次输入的原始 Key 会存在于本机输入框内存和提交请求中，用户自己的开发者工具能检查它。后续本地存储是加密包。后端在转发时能够解密；不能宣传“网站运营者也看不到”。其他访客没有读取通道，但同一个浏览器配置文件、恶意扩展、XSS 和凭证复制不属于不同访客隔离可以独自解决的范围。

加密包是可重放的调用凭证；不要分享。删除配置不能让已经复制出去的包自动失效，需撤销原始供应商 Key。当前没有逐包吊销表。轮换时设置新的 active ID 并保留旧 key，旧包继续有效；移除旧 key 将使使用该 key 的全部旧包失效。

## 更新 Skill

`npm run skills:sync` 默认从当前用户的 `.agents/skills` 读取两个 Skill；也可用 `node scripts/sync-skills.cjs /path/to/skills` 指定来源。脚本按发布资源规则同步 Skill、目录及支持资料，拒绝符号链接，生成内容哈希清单。同步后检查差异并重新测试、构建。运行时只能读取清单内固定资源，没有用户指定文件路径的入口。

## 账号和公众号的下一步

已建立 `AuthAdapter`、`AccountCredentialRepository`、`WechatDraftAdapter` 接口。默认全部未配置，`/api/account/session` 返回 guest，公众号草稿接口拒绝未登录调用，没有模拟登录或虚假的同步成功结果。

接入真实登录后，服务端从会话取得用户身份；账号凭证由仓库按用户查询和加密保存。浏览器只使用账号凭证 ID，不返回密文或明文。账号凭证通路尚未实现，不应直接复用访客加密包作为跨账号授权。

公众号接入需落实实际授权方式、账号权限、素材上传、文章图片替换和幂等草稿同步。`WechatDraftAdapter` 仅定义服务边界；当前路由刻意保持关闭，直到真实授权、素材上传和幂等验收完成。不能把公众号网页的登录 Cookie 当成 API 授权，也不把创建草稿当成发布文章。

## 验证

- `npm test`：凭证随机性、篡改拒绝、地址/供应商/空间绑定、轮换、存储恢复和失败保护、账号归属、Skill 输入边界，及原有排版/存储测试。
- `npm run typecheck`、`npm run build`、`node scripts/css-audit.cjs`。
- 服务启动后运行 `node scripts/verify-local-api.cjs` 和 `node scripts/verify-credential-framework.cjs`：只使用本机模拟模型，检查生产 API 的全链路。
- 浏览器实测：填写一次、关闭标签重开、已保存 Key 不回显、文字与配图连接测试。结果记录在 `docs/validation/`。真实付费供应商、公网部署、真实登录及微信草稿写入需在配置后另行验证。
