# 版本更新后旧页面代码加载修复

历史记录：本文记录统一 GitHub 发布之前的兼容修复；后续发布以 /api/release 和 GitHub Actions 为准。

2026-10-30 已发布至原 Worker `kaipai`，生产版本 `5f632cdd-410a-49d4-9928-4769d35faa44`，公共缓存版本 `ee90179c68f8773fb9e1`。Cloudflare 确认 100% 流量使用此版本。原生产版 `e48cc5d0-c346-480e-b24f-b9c19214b343` 保留在平台历史中；直接回退到它会重新移除旧资源，不能作为兼容性无损的回退方案。

## 原因与修复

旧 Service Worker 保留首页及常用模块，未遍历构建清单的 `dynamicImports`；本机 AI 客户端属于按需模块。下一次发布替换了 Workers 静态文件集，仍在运行的旧页面请求 `DiszO2SV.js` 时得到 404。

本次从两个历史版本预览地址取回 43 个公开 JS/CSS，并逐一核对各版 `/sw.js` 中的 SHA-256。`cloudflare/asset-history/` 保留原始文件；发布构建同步当前生产清单，将旧代码合并进新包。上传前再次校验当前生产资源，缺少文件或相同路径字节不同都拒绝发布。

新缓存递归包含静态与动态依赖，并保留历史模块。遇到缓存的错误响应时绕过一次重新获取；全部校验后，只给已有完整旧缓存补齐缺失的公开模块，不替换旧 HTML、不强制刷新页面、不接触文稿和凭证。

生产候选来自上一版生产源码归档，原 `app/`、`lib/` 逐文件未变，应用构建文件名与上一版一致。根工作区其他未发布改动没有上线。本次未向 GitHub 推送。

## 验证结果

- 工作区 `npm test`、`npm run typecheck`、CSS 检查通过；隔离生产源码的 Next.js 与 Cloudflare 构建通过。
- 隔离生产候选逐套检查 36 套测试，35 套通过。唯一失败仍是已知的 `tests/v4-styles.test.ts` ordinary-bold 断言，测试和渲染代码与原生产归档相同。本次新增资源历史、发布门禁、动态依赖、缓存错误响应恢复和旧缓存补齐断言均通过，没有更新排版快照。
- 在两个真实旧版浏览器页面保持打开时模拟发布：原方案复现同一 `DiszO2SV.js` 错误，保留旧文件后模型测试通过，页面未刷新。模型请求仅调用本机免费模拟接口。
- 最终缓存安装后，曾报错的旧缓存得到补齐。关闭资源服务后，旧页面首次加载本机模型模块仍测试通过，页面继续使用旧首页。新缓存本身也通过资源服务关闭后的测试。
- 最终线上 Workers 备用入口的 43 个历史文件全部返回 200，SHA-256 全部匹配。正式域名原报错文件亦返回 200 且哈希匹配，`/api/platform` 返回 200。

## 未通过的验收与发布来源

当前电脑访问正式域名仍有独立的连接超时、`fetch failed`。最终逐文件复查中，27/43 个文件返回 200 且哈希一致，16 个请求在连接或传输阶段失败；没有收到 HTTP 错误状态。浏览器模型测试仍等待网络，已主动取消，未记为通过。不能把备用入口、局部 200 或本地通过当作正式域名网络稳定。曾清理报错文件的精确 CDN URL 缓存，没有清理整个站点、修改网络设置或清除用户浏览器存储。

GitHub 自动与手动发布流程存在，但最近一次成功运行在 2026-10-22；之后生产通过隔离本机归档发布。不能重跑旧 GitHub main 覆盖较新的线上功能。统一发布来源需另行把已验证生产代码与仓库对齐。
