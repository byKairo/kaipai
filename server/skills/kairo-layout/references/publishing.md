# 发布排版

用户要求公众号 HTML、网页预览或可复制的排版文件时读取。先确定本次已采纳的内容，再转换，不在转换时再次悄悄改稿。建议模式可以在副本展示明确标注的拟议效果；正式复制与导出只能包含原文及用户已经采纳的改动，不能把审阅标记、修改理由或未采纳的高亮混进去。此文件与随附检查脚本可独立使用，不依赖其他 Skill、固定项目或私人知识库。

## 输出与标题

先保存最终 Markdown，再生成同一份内容的 HTML。公众号标题有独立输入框，默认把 Markdown 开头的第一个一级标题写入 `<title>`，正文从实际内容开始，避免重复大标题。用户要求正文显示标题时可以保留；后续一级标题按正文层级处理。

网页阅读版本可以显示大标题。说明它与公众号复制版本的区别，不能混用两个交付的验收条件。

输出 UTF-8，自包含，带 `lang="zh-CN"`、字符集和 viewport。示意结构如下，正式文件的可见元素都需有完整行内样式。

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>文章标题</title>
</head>
<body style="max-width:720px;margin:0 auto;padding:24px 22px;background-color:#ffffff;">
  <p style="font-family:-apple-system,BlinkMacSystemFont,'PingFang SC','Microsoft YaHei',sans-serif;font-size:16px;line-height:1.82;color:#292d35;margin:14px 0;">正文</p>
</body>
</html>
```

## 选择视觉参数

以文章用途和用户偏好选择，不强制一套风格。

| 文章形态 | 建议起点 | 需要保护的内容 |
|---|---|---|
| 个人手记、叙事、观点 | 近白底、深灰字、温和的章节层级、少量强调 | 作者声音、自然段节奏与叙事顺序 |
| 教程、工具说明、开发记录 | 浅色底、清楚的章节与步骤、等宽代码、紧邻的参数说明 | 操作依赖、条件、复制文本与结果判据 |
| 分析与比较 | 克制配色、清楚的论证层级、必要的比较表或分组 | 证据归属、限定词与比较维度 |

正文可从 16px、1.75–1.95 行高、12–18px 段距开始；二级标题可从 19–22px、三级标题从 17–18px 开始。代码可从 13–14px 等宽字、1.5–1.7 行高开始。根据篇幅、字体、阅读宽度与实际预览调整，不称这些参数为普遍最优标准。

普通段落保持自然高度，标题间距表达章节关系，代码区和必要说明区可用浅底色。不要把全文包成等高卡片，或让装饰抢过内容。

## 公众号兼容规则

- 为每个可见段落、标题、列表容器和列表项、代码、强调、引用和表格元素写入所需 `style`。正文基础字号、行高、颜色和字体不得只靠 body 或外层容器继承。
- 正式交付不用 `<style>`、class / id 选择器、伪元素、外部字体、脚本、动画和固定定位。body 只负责本地预览的宽度、页边距与背景；普通正文尽量用扁平结构。
- 优先用字体、颜色、间距、边框和单色背景表达层级，减少依赖复杂 CSS。HTML 特殊字符必须转义。
- 保留中文句号与必要标点。空行分段，普通 Markdown 单个换行按语义合并，代码块与有意义的分行不得合并。
- 保留有序 / 无序列表的区别。真实引用才用引用块，作者自己的重点句可用加粗或视觉强调，不伪装成他人引文。
- 保留代码真实字符与换行；用 CSS 处理长行，不能在源文本中加换行、删空格或拆字符串来适配手机。
- 表格按实际比较关系处理。载体需要转成分组列表时，逐项保留标题、数据与对应关系，并说明结构变化。转换困难就报告具体问题，不能默默丢掉表格。
- 链接显示为有意义的名称和可复制地址；不用外部资源加载。URL 可以作为正文或代码中的文字出现，不能把这种文字误报成外部资源请求。
- 图片地址、上传与复制状态应区分。没有接通公众号图片上传时，不把本地或 Base64 图片当成已发布素材；可以保留明确的待插图位置。不要替用户安装插件或上传素材。

## 内容与结构检查

生成后运行：

```text
python3 <本 Skill 目录>/scripts/check_delivery.py 排版稿.md 排版预览.html
```

脚本只依赖 Python 标准库，检查标签、行内样式、外部资源、首标题和代码文本。如果用户要求正文保留一级标题，增加 `--body-title`。检查失败时修正具体问题，重新执行；不能为了通过检查改变文章事实或代码内容。

脚本通过后仍要核对正文完整性、链接、列表顺序、表格对应关系和重点。它不证明文稿的语义或编辑质量，也不能证明微信公众号会保留全部样式。

在可用的预览能力中检查窄屏正文、标题、强调和最长代码行。有浏览器策略或工具权限限制时，交付文件并说明未完成视觉验证，不换地址、浏览器或运行方式绕过限制。

公众号后台粘贴与手机预览只有实际完成才能称为已验证。没有该验证时，可以说明用户手动打开 HTML、全选复制正文、粘贴到后台，再用手机预览检查。不能把复制成功等同于发布成功。
